## 2. 최근 개선된 문제

### 인벤토리/무기

- 장비 슬롯 드래그 시 서버에 잘못된 슬롯 번호가 전달되어 주무기/보조무기가 덮어써지던 문제를 수정했다.
- 1번/2번 전환 직후 이전 무기가 발사되거나 비무장 상태가 되는 흐름을 보정했다.
- 회복 아이템이 탄약 또는 다른 아이템으로 덮어써지는 문제를 인벤토리 동기화/아이템 key 처리 정리로 개선했다.
- 인벤토리 밖 드래그 드랍 기능을 추가했고, 수량 선택 UI를 붙였다.
- 가방 무게 제한은 `DEFAULT_MAX_CARRY_WEIGHT = 150.0f`로 조정했다.

### 문/집/좀비

- 각 집에 상하좌우 4방향 문을 생성한다.
- 문은 F키로 열고 닫을 수 있고, 닫힌 문은 플레이어와 좀비 모두 통과하지 못한다.
- 문과 파밍박스가 겹치는 상황에서는 문 상호작용을 우선한다.
- 밤에는 좀비가 문을 공격할 수 있다.
- 문 공격 대상은 맵 전체 좀비가 아니라, 플레이어가 있는 집 주변 반경 내 좀비로 제한했다.
- 문이 부서지면 해당 좀비들은 문 타겟을 해제하고 플레이어 추적으로 돌아간다.
- 플레이어가 집 안에 있고 문이 모두 닫혀 있거나 문이 부서진 침입 상황이면 해당 집 내부 좀비 리스폰을 막는다.
- 일부 문이 지붕 위로 보이거나 내부가 보이지 않던 렌더링 문제를 개선했다.

### 파밍/맵/탈출

- 파밍박스 수를 늘리고, 집 안에만 몰리지 않도록 실외에도 분산 배치했다.
- 서버 실행 시 맵이 자동 재생성되도록 `run_server.sh`에서 `generate_map.py`를 호출한다.
- 탈출존은 `map.json` 기준으로 로드되며, 클라이언트도 같은 맵 데이터를 사용한다.
- 탈출존 근처에서 F키 안내와 채널링 진행률을 표시한다.
- 탈출 진행 패킷의 `zoneID`는 `ExtractionSystem::channelZoneID()`로 실제 채널링 존을 전송한다.

## 3. 남은 리스크 및 확인 필요 항목

| 항목 | 상태 | 확인 내용 |
|---|---|---|
| 멀티 클라이언트 통합 테스트 | 필요 | 2명 이상 접속 시 인벤토리, 문, 탈출, 라운드 리셋 동기화 확인 |
| friendly-fire 정책 | 확인 필요 | 근접은 같은 팀 피해 차단, `applyDamage()` 직접 경로는 팀 PvP 허용 주석이 남아 있어 기획 확정 필요 |
| 사운드 파일 누락 | 확인 필요 | `sounds.json`의 모든 key가 실제 wav와 매칭되는지 런타임 로그 확인 |
| 좀비 수 증가 후 성능 | 확인 필요 | 좀비 수가 늘면서 O(N²) 순회가 체감되는지 확인 |
| DB 시작 프로세스 | 개선 완료 | `start_deadzone.command` 더블클릭 또는 `scripts/setup_database.sh` 실행으로 로컬 MySQL DB, 앱 계정, 테스트 로그인(`test` / `test1234`)을 생성하고 `.env.server`를 작성 |
| 자동 맵 재생성 | 주의 | `run_server.sh` 실행 때 `data/map.json`이 매번 갱신되므로 테스트 맵 고정이 필요하면 옵션화 필요 |

## 4. 개선 우선순위

### 높음

- 멀티 2인 이상 접속으로 장비 전환, 아이템 드랍, 문 열기/닫기, 문 파괴, 탈출까지 통합 테스트.
- friendly-fire 정책 확정 후 `CombatSystem::applyDamage()` 주석과 실제 동작 일치.
- `sounds.json`에 정의된 사운드와 실제 `assets/sounds/*.wav` 매칭 검수.

### 중간

- 좀비 탐색/공격 순회 최적화. 현재는 전체 엔티티 순회가 많아 좀비 수를 더 늘리면 병목 가능성이 있다.
- 자동 맵 재생성 on/off 옵션 추가. 예: `DEADZONE_REGENERATE_MAP=0 ./run_server.sh`.
- 문 HP/좀비 문 공격 데미지 밸런스 조정.

### 낮음

- 문서와 발표자료에 최신 기능 반영.
- 사운드 생성 스크립트 실행 방법을 README 또는 제출 체크리스트에 추가.
- 디버그 오버레이 또는 서버 로그로 좀비 문 타겟팅 상태를 시각적으로 확인하는 도구 추가.
